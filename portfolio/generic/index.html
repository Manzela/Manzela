Page 1 — TNG Shopper

TNG Shopper — production multi-agent system | Co-founder CEO/CPO + Lead Product Engineer | Jan 2024 – present

Identity

TNG Shopper is an AI content engine for multi-location brands. The system writes, distributes, and continuously updates content across hundreds of retailer sites so the brand wins organic traffic from AI Search (ChatGPT, Claude, Perplexity, Google AI Overview) at a unit cost the retailer can defend. Customers are enterprise retailers running 10–500 stores per chain. The problem the system solves is the one no human SEO team can solve at that scale: produce defensible, schema-correct, AI-readable content on every product page across every locale, refresh it as the catalog turns, and prove the lift to the CMO who signed the contract.

Architecture (the 7-node DAG)

Architecture is the 7-node multi-agent DAG visible at manzela.github.io/pipeline-observatory/#dag. Each node is a deterministic gate paired with a probabilistic agent — never the reverse. The first six nodes run in production: brief intake, retrieval over the customer’s canonical SKU catalog, draft generation, deterministic O‑R‑A‑V gating (Observe diagnostics → Reason about severity → Act with corrections → Validate the final output), schema injection, and cross-site distribution. The seventh node — a reinforcement step on accumulated O‑R‑A‑V signals — is in Langfuse R&D and not yet in the production code repo; the public claim of 7-node DAG stands. Stack: Google ADK for the agent runtime; Vertex AI hosting Gemini 3.1 Flash-Lite for the bulk content path and Gemma 4 26B-A4B-it MoE (128 experts, 4 active per token; 4B params per forward pass on a 26B model) for the harder rewrite class; Modal serverless for burst capacity with a vLLM fallback when Vertex quota saturates; Langfuse for observability and trace replay; Pydantic for the typed agent contracts; OPA for policy-as-code on the deterministic gates; asyncio runtime end-to-end. Built and led by a 2-engineer team over 18 months; Daniel = ~74% of commits.

Atelier — autonomous design agent | Solo architect + lead engineer | May 2026 – present

Identity

Atelier is an autonomous design agent that converges UI/UX work to flawless across multi-axis judged criteria instead of generating one-shot output and stopping. Every shipped autonomous-design tool today — Stitch, Vercel v0, Subframe, Lovable.dev, Replit Agent, Devin, Builder.io Fusion, Tempo Labs — terminates at generation; Google’s own Antigravity codelab calls the verification step “Vibe Check” (manual eyeballing). Atelier asks the right questions, converges autonomously, learns each project’s preferences, handles multi-surface campaigns, and renders to any framework. Submission target: Google for Startups AI Agents Challenge 2026, files 2026-06-03 noon (2 days before the 2026-06-05 deadline). Prize pool $90K plus mentorship from DeepMind and Google Labs.

Architecture

Three layers. Layer 3 — Pre-Generation Intake Protocol (PIP) runs adaptive Q&A mapped 1:1 to documented coding-agent failure patterns; output is an immutable BriefSpec the agent commits to and a seeded DECISIONS.md. Layer 2 — Campaign Orchestrator handles cross-surface coherence across multi-session campaigns via Cloud Scheduler + Cloud Tasks. Layer 1 — Atomic 8-node DAG runs per-surface: Brief Parser → Source Resolver → EvoDesign LoopAgent → Final Validator + A2UI Renderer. Inside the LoopAgent: Generator (ParallelAgent K=6 candidates via Stitch MCP) → Constitutional Self-Critique → Deterministic Gate (parallel × 6 axes — Lighthouse, axe, visual-diff, token-fidelity, responsive, semantics) → ConsensusAgent (5 specialized rubric judges with DEMAS-D Per-axis Provenance Matrix) → Fixer (Hebbian mutator via adk optimize / GEPA). Built on Google ADK 2.0 Beta + Vertex AI + Stitch MCP + A2UI v0.9. Architecture inspired by the production-validated 7-node Gate-Agent DAG in agent-dag-pipeline and the long-running-agent harness pattern from Anthropic’s published guidance (Nov 2025).

13 novel contributions

  • N1 — DGF-D2C — Deterministic-Gate-First Design-to-Convergence. Improves on WebGen-Agent (NeurIPS 2025 SOTA at 51.9%) by adding deterministic preconditions before any judge call. Eliminates judge attention dilution.
  • N2 — DEMAS-D — Per-axis Provenance Matrix Design Judge. Each axis (a11y, brand, motion, copy, semantics, tokens) sees only its relevant ground-truth variables — never the full DOM.
  • N3 — PerJudge — Per-Project DPO Judge with Hebbian Mutator + Few-Shot Cold-Start. Addresses DesignPref’s α=0.25 finding (designer disagreement is intrinsic). Personalized judges win with 20× fewer examples.
  • N4 — PADI — Project-Agnostic Descriptor Inference. Adapts to any tech stack with optional .atelier.yaml descriptor; full inference from path + intent.
  • N5 — EvoDesign — AlphaEvolve-Inspired Evolutionary K-Candidate Search. First transfer of DeepMind’s AlphaEvolve methodology to UI generation. K=6 candidates × 8 mutation operators per iteration.
  • N6 — CSC-D — Constitutional Self-Critique for Design. Self-grades each candidate against the 12-principle Apple-Grade constitution before deterministic gate fires.
  • N7 — A2UI-Native Output — First autonomous design agent built on Google’s A2UI v0.9 protocol from day one. Renders to React + Flutter + Lit + Angular simultaneously.
  • N8 — Public Judge Calibration Dashboard — First commercial autonomous design agent to publish judge calibration externally as a transparency commitment. Defends against the calibration-drift problem 93% of teams hit.
  • N9 — Open Eval Adapters Library — Apache-2.0 PRs to google/adk-python for WebGen-Bench, Design2Code, Web2Code, ScreenSpot, FrontendBench. Makes ADK the canonical evaluation runtime for the field.
  • N10 — Convergence Spec RFC — Open standard: how an autonomous design agent declares convergence criteria, emits trajectories, reports calibration drift. Atelier is the reference implementation.
  • N11 — Public Eval Harness — bench.atelier.dev accepts agent submissions from any vendor. Atelier becomes the standard evaluation surface for the entire UI-generation field.
  • N12 — RLRD — Recursive Long-Running Discipline. Atelier-as-reference-implementation of Anthropic’s published long-running agent harness for a domain-specific agent. The same patterns we use to build Atelier, we ship to users running multi-day, multi-surface campaigns.
  • N13 — PIP — Pre-Generation Intake Protocol. Adaptive-depth, DAPLab-pattern-mapped, visual-option-driven, skip-when-answered intake. First commercial autonomous design agent to ship structured pre-generation intake.
